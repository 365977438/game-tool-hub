腾讯混元 Hy4 实测：多模态 Agent 能独立交付游戏 Demo

腾讯混元 Hy4 以 770B 总参数、49B 激活参数引入原生视觉、电脑操作和长程 Agent 能力。在 WorkBuddy 实测中，它依据截图制作复古音乐播放器，并自主启动无头 Chrome 测试界面，为游戏原型与前端交互开发提供了可执行的新路径。

💡 Hy4 已展示从截图理解、编码到浏览器自测的连续交付链，显著缩短可交互原型制作路径。

关键要点

  • 拆解截图并生成可交互界面，复用视觉参考
  • 调用无头浏览器完成界面点击与视觉回归
  • 用 Web Audio 补充原型测试所需音乐
  • 优先将 Agent 用于原型、UI 与局部验收

正文（AI 核查整理）

腾讯混元 Hy4 已正式发布，并以 770B 总参数、49B 激活参数进入开源模型阵营前列。它首次加入原生视觉理解和电脑操作能力，同时强化指令遵循、长文理解与长程 Agent 任务；模型权重计划于近期开源，API 已接入 OpenRouter、Hermes、OpenCode 等平台。

在 WorkBuddy 中，Hy4 接收了制作复古音乐播放器的任务。它先从设计截图拆解配色、字体、布局和像素尺寸，再编写页面与播放功能。成品包含导航、歌单、播放区和待播列表，并支持播放暂停、切歌、进度拖动、音量调节、循环、随机播放、搜索与收藏。

Hy4 还用 Web Audio 实时生成三首测试音乐，无需开发者另外准备音频素材。完成编码后，它在沙盒中启动无头 Chrome，逐项点击、拖拽界面并截图进行视觉差异比较；首轮 51 项测试通过 48 项，剩余问题也由其自行定位和继续修正。

这套流程对游戏开发者尤其有参考价值：视觉参考图可以被直接转化为可交互界面，浏览器环境也能承担基础验收。制作菜单、HUD、设置页、活动页或可玩原型时，开发者可让 Agent 同时承担视觉还原、代码实现、测试素材补充和回归检查，而不必逐项手工操作。

更早的测试还显示，Hy4 能制作带爆炸结构视图和按键物理动效的 3D 机械键盘 Demo，模型权重开源后也具备接入自有工具链的可能。不过素材未给出独立游戏项目中的稳定性、成本和美术质量数据，现阶段更适合用于原型验证与局部工作流，而非直接替代完整制作团队。
