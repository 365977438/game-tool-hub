工具介绍

godot-ci 是面向 Godot 的持续集成工具，用于将游戏项目接入自动化构建与测试流程。它适合需要反复导出、验证和发布项目的开发者与团队，具体能力取决于部署配置。

核心能力

  • 面向 Godot 项目
  • 支持持续集成流程
  • 可衔接自动构建与测试任务

👍 优点

  • 有助于减少重复发布操作
  • 适合建立稳定的项目交付流程

⚠️ 局限

  • 需要配置持续集成环境
  • 社区项目，文档与支持有限

典型使用场景

  • 为 Godot 游戏设置自动构建流程
  • 在提交后自动导出并验证游戏版本

使用教程

入门⏱ 约 20 分钟🎯 构建一次游戏并自动完成线上发布
  1. 1

    准备项目与发布凭据

    在本地创建 Godot 项目并确认可正常运行；进入 GitHub 或 GitLab 仓库的 Settings、Secrets，添加 Itch.io API Key 等发布凭据。

  2. 2

    配置容器导出参数

    依据仓库文档编写 Docker 导出配置，指定 Godot 版本、导出预设、项目目录和产物路径；先用本地命令验证镜像能够生成游戏。

  3. 3

    接入 GitHub Actions

    在仓库 Actions 页面新建工作流，复制 godot-ci 的 GitHub Actions 模板，填写导出配置与 Secrets 名称，并确认构建产物上传步骤。

  4. 4

    或接入 GitLab CI

    打开 GitLab 项目的 CI/CD 页面，复制仓库提供的 GitLab CI 模板并加入 .gitlab-ci.yml，在 Variables 中配置同名凭据后提交。

  5. 5

    运行并检查导出产物

    提交配置文件触发流水线，在 Actions 的运行记录或 GitLab CI 页面查看日志，确认导出成功、压缩包生成且下载产物与预期一致。

  6. 6

    启用自动部署

    按目标启用 GitHub Pages、GitLab Pages 或 Itch.io 模板，填写站点路径与上传信息；重新运行流水线，检查公开地址或游戏页面。

💡 实用技巧

  • 固定 Godot 镜像版本，避免升级后导出失败
  • 先手动导出一次，再接入自动流水线
  • 密钥只放在 Secrets 或 Variables 中
  • 为 Pages 配置正确的站点基础路径

⚠️ 常见坑

  • 导出预设名称与配置文件不一致会失败
  • 首次触发流水线前必须提交模板文件
