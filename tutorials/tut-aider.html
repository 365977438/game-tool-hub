Aider 入门：用 AI 修改并提交游戏代码

面向独立游戏开发者，演示在终端中配置 Aider、读取项目、生成补丁、运行测试并用 AI 辅助提交代码。

关联工具AIAider官网 ↗
入门⏱ 约 20 分钟🎯 让 AI 完成一次游戏代码修改并提交 Git
  1. 1

    安装并配置模型

    打开终端，按官网说明安装 Aider，再运行 aider；根据提示填写模型服务商的 API Key、模型名，并确认可正常对话。

  2. 2

    进入游戏项目目录

    在终端 cd 到包含游戏源码的仓库，先用 git status 检查状态并提交或暂存现有改动，避免 AI 混入无关文件。

  3. 3

    添加项目上下文

    在 Aider 中使用 /add 添加角色脚本、玩法系统等关键文件；也可配置项目说明文件，让 AI 理解引擎、目录与编码规范。

  4. 4

    描述并应用修改

    用明确提示词描述目标，例如“给玩家增加双击冲刺并补充冷却逻辑”。检查 diff 后用 /diff 查看，再执行 /apply 接受补丁。

  5. 5

    运行验证与修正

    按项目方式运行测试、编译或启动游戏；把报错交给 Aider 分析，继续应用修复，直到功能表现正确且没有回归。

  6. 6

    审查并提交代码

    运行 aider 的提交功能，让 AI 根据改动生成 Git 提交信息；检查暂存文件和 commit 内容后完成提交，将成果纳入版本管线。

💡 实用技巧

  • 提示中写清输入、行为与验收标准
  • 小步修改，每次只实现一个玩法
  • 让 AI 先分析再要求落地补丁
  • 运行日志和关键源码可按需加入上下文

⚠️ 常见坑

  • 不要把 API Key 写进项目文件
  • 提交前检查 AI 生成的完整差异

常见问题

Q：首次运行 Aider 时模型该怎么填写？

启动 aider 后，按提示填写模型服务商的 API Key 和模型名，随后发送一条简单消息确认能正常对话。API Key 不要写进项目文件，避免进入 Git 提交。

Q：如何避免 AI 修改到无关文件？

进入游戏仓库后先运行 git status，提交或暂存已有改动，再用 /add 添加角色脚本、玩法系统等必要文件。每次让 AI 只实现一个小玩法，并在 /apply 前用 /diff 检查补丁。

Q：补丁通过检查后怎样接入游戏验证和提交？

执行 /apply 接受补丁后，按项目方式运行测试、编译或启动游戏；若有报错，将日志交给 Aider 修复。验证通过后使用 Aider 的提交功能生成提交信息，并检查暂存文件与 commit 内容。
