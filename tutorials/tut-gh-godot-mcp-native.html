Godot MCP 入门：连接 AI 操作引擎

从安装 Godot MCP Native、配置 AI 客户端到执行首个场景命令，快速掌握用自然语言创建节点、修改属性与运行项目的方法。

入门⏱ 约 20 分钟🎯 让 AI 客户端成功连接 Godot 并执行操作
  1. 1

    准备 Godot 与 AI 客户端

    安装 Godot 4.x，并打开 Cursor、Claude Code 等支持 MCP 的客户端。确认项目能够正常启动，再开始配置连接。

  2. 2

    获取并配置 MCP Server

    克隆 GitHub 仓库，按 README 找到启动命令，将其作为 HTTP MCP Server 添加到 AI 客户端。端口须与 Godot 插件配置一致。

  3. 3

    启动 Godot MCP 服务

    在项目终端运行仓库提供的启动脚本或命令，保持进程运行。随后检查端口监听状态，确认服务可被客户端访问。

  4. 4

    完成客户端连接测试

    在 AI 客户端的 MCP 设置中启用该服务，新建对话并询问 Godot 项目信息。若返回场景或节点数据，说明连接成功。

  5. 5

    执行首个自动化操作

    输入“创建一个 Sprite2D 节点并命名为 Player”等指令。检查 Godot 场景树中的新增节点，必要时让 AI 重新执行或修正。

  6. 6

    验证并保存项目

    让 AI 读取节点属性、修改位置或运行项目，观察编辑器和输出面板。确认结果正确后保存场景，并逐步扩展更复杂的工作流。

💡 实用技巧

  • 优先使用仓库 README 中的最新配置示例
  • 先测试读取信息，再执行场景修改
  • 每次只下达范围明确的小任务
  • 项目操作前先建立 Git 提交

⚠️ 常见坑

  • 端口不一致会导致客户端连接失败
  • 关闭终端进程会中断 MCP 服务

常见问题

Q：安装后客户端连不上 Godot 怎么办？

先检查 Godot 插件与 AI 客户端配置的端口是否一致，再确认启动 MCP Server 的终端进程仍在运行。可查看端口监听状态；统一端口并重启服务后，在客户端重新启用该服务并测试读取项目信息。

Q：关闭终端后 AI 操作会失效吗？

会。Godot MCP 服务依赖终端中的启动脚本或命令，关闭终端或结束进程就会中断服务。需要继续操作时，保持该进程运行，并在客户端重新检查连接状态。

Q：怎样降低自动修改场景出错的成本？

先让 AI 只读取场景或节点信息，确认连接正常后，再执行“创建 Sprite2D 并命名为 Player”这类小任务。每次只下达范围明确的指令，操作前建立 Git 提交，便于核对和修正节点或属性改动。
